# Bytecode Mapping Fix - Blue Book Specification

## Summary
Fixed incorrect bytecode ranges in `BytecodeDispatcher.cs` to match the Smalltalk-80 Blue Book specification exactly.

## Changes Made

### Previous INCORRECT Mapping:
- 16-31: Push Temporary Variable
- **32-47: Store Temporary Variable** ❌
- **48-63: Push Argument** ❌  
- **64-71: Push Literal Constant** ❌
- **72-79: Push Literal Variable** ❌

### Corrected Blue Book Mapping:
- 0-15: Push Receiver Variable ✓
- 16-31: Push Temporary Location ✓
- **32-63: Push Literal Constant** ✓
- **64-95: Push Literal Variable** ✓
- **96-103: Pop and Store Receiver Variable** ✓
- **104-111: Pop and Store Temporary Location** ✓
- 112-119: Push special constants (receiver, true, false, nil, -1, 0, 1, 2) ✓
- 120-123: Return operations ✓
- 124: Return Top of Stack from Message ✓
- 125: Return Top of Stack from Block ✓
- 128-191: Send operations ✓
- 192: Extended Send ✓
- 208-215: Jump operations ✓
- 216-218: Conditional jumps ✓
- 224-255: Special selectors/extended operations ✓

## New Methods Added
1. `PushReceiver()` - Push receiver onto stack (bytecode 112)
2. `PushConstant()` - Push constant values onto stack (bytecodes 113-119)
3. `PopAndStoreReceiverVariable()` - Pop stack and store in receiver variable (bytecodes 96-103)
4. `PopAndStoreTemporaryVariable()` - Pop stack and store in temporary variable (bytecodes 104-111)

## Removed Methods
1. `StoreTemporaryVariable()` - No longer needed (was for incorrect range 32-47)
2. `PushArgument()` - No longer needed (was for incorrect range 48-63)

## Impact
This fix ensures the interpreter correctly executes bytecode generated by the Smalltalk-80 compiler, which follows the Blue Book specification. The incorrect mappings would have caused:
- Literal constants to be misinterpreted
- Literal variables to be accessed incorrectly
- Store operations to fail
- Special constant pushes to be unavailable

## Verification
The updated code compiles successfully with no errors or warnings.
