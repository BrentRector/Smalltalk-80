## Heap Manager Architecture

### Overview

The heap manager provides a clean, low-level API for Smalltalk object allocation and access, completely separated from high-level semantic knowledge. It uses tagged OOPs for SmallIntegers and ObjectTable indirection for heap objects.

### Core Components

#### ISmalltalkHeapManager Interface

```csharp
public interface ISmalltalkHeapManager
{
    // Object Allocation
    SmalltalkOOP AllocateObject(SmalltalkOOP classOOP, ObjectFormat format, 
                               int fixedSlots, int indexedSize);
    
    // Instance Variable Access (always OOPs)
    SmalltalkOOP GetInstanceVariable(SmalltalkOOP objectOOP, int index);
    void SetInstanceVariable(SmalltalkOOP objectOOP, int index, SmalltalkOOP value);
    
    // Format-Specific Indexed Access
    SmalltalkOOP GetIndexedOOP(SmalltalkOOP objectOOP, int index);        // Arrays
    void SetIndexedOOP(SmalltalkOOP objectOOP, int index, SmalltalkOOP value);
    
    byte GetIndexedByte(SmalltalkOOP objectOOP, int index);               // Strings/Floats
    void SetIndexedByte(SmalltalkOOP objectOOP, int index, byte value);
    
    ushort GetIndexedWord(SmalltalkOOP objectOOP, int index);             // Bitmaps
    void SetIndexedWord(SmalltalkOOP objectOOP, int index, ushort value);
    
    // Object Metadata
    SmalltalkOOP GetClassOOP(SmalltalkOOP objectOOP);
    ObjectFormat GetObjectFormat(SmalltalkOOP objectOOP);
    int GetInstanceVariableCount(SmalltalkOOP objectOOP);
    int GetIndexedSize(SmalltalkOOP objectOOP);
    
    // GC Root Management
    void SetGCRoots(SmalltalkOOP[] rootObjects);
    void AddGCRoots(SmalltalkOOP[] additionalRoots);
    SmalltalkOOP[] GetGCRoots();
    
    // Garbage Collection
    GCStatistics GarbageCollect();
    GCStatistics GetGCStatistics();
}
```

#### Tagged OOP System

```csharp
public readonly struct SmalltalkOOP
{
    private readonly int _value;
    
    public bool IsSmallInteger => (_value & 1) == 1;
    public bool IsObjectPointer => (_value & 1) == 0;
    
    public int AsSmallInteger() => _value >> 1;
    public int AsObjectTableIndex() => _value >> 1;
    public int AsRawValue() => _value;
    
    public static SmalltalkOOP FromSmallInteger(int value) => new((value << 1) | 1);
    public static SmalltalkOOP FromObjectTableIndex(int index) => new(index << 1);
}
```

#### Object Format Enumeration

```csharp
public enum ObjectFormat : byte
{
    Pointer = 0,          // Fixed instance variables only
    PointerIndexed = 1,   // Instance variables + indexed OOPs (Arrays)
    ByteIndexed = 2,      // Instance variables + indexed bytes (Strings)
    WordIndexed = 3,      // Instance variables + indexed words (Bitmaps)
    CompiledMethod = 4    // Special format for methods
}
```

### Key Architectural Benefits

1. **No Semantic Knowledge**: Heap manager doesn't know about classes, symbols, or special objects
2. **Type Safety**: Format-specific access methods prevent wrong data type access
3. **Bounds Checking**: All array accesses are validated against object bounds
4. **Tagged Pointers**: SmallIntegers stored directly in OOPs for efficiency
5. **Flexible GC Roots**: Cold start can configure any combination of root objects

### GC Root Management

The heap manager provides a flexible root management system that replaces the traditional Special Objects Array approach:

```csharp
// Set initial GC roots during cold start
var gcRoots = new[]
{
    SmalltalkOOP.FromObjectTableIndex(GlobalRegistry.NilObjectId),
    SmalltalkOOP.FromObjectTableIndex(GlobalRegistry.SystemDictionaryId),
    SmalltalkOOP.FromObjectTableIndex(ustableId),
    // ... additional roots
};
_heapManager.SetGCRoots(gcRoots);

// Add temporary roots during validation
_heapManager.AddGCRoots(temporaryValidationObjects);

// Perform GC with detailed statistics
var stats = _heapManager.GarbageCollect();
```

## JSON Cold Start Format

### Schema Version 1.0.3

The current JSON schema supports the v1.0.3 block compilation approach where blocks are separate CompiledMethod objects:

**Key Features:**
- **Blocks as Methods**: Each block compiles to a separate CompiledMethod with `selector: null`
- **Ownership Tracking**: `blockOwnerMap` records which method owns each block
- **Blue Book Bytecodes**: Standard bytecode instruction set, no special block instructions
- **Literal References**: Blocks reference other blocks via `compiledMethod` literal type

**Schema Location:** `docs/schemas/coldstart-v1.0.3.schema.json`

### Bundle Structure

```json
{
  "version": "1.0.3",
  "metadata": {
    "symbolCount": 3914,
    "stringCount": 6324, 
    "classCount": 474,
    "methodCount": 10059,
    "initExpressionCount": 285
  },
  "symbols": ["#symbol1", "#symbol2", ...],
  "strings": ["string1", "string2", ...],
  "classes": [...],
  "objects": [...],
  "methods": [...],
  "patches": [...],
  "initExpressions": [...],
  "optimizedSelectors": [...]
}
```

### Method Descriptor Format

```json
{
  "localId": "method:1234",
  "homeClassLocalId": "class:Object",
  "selectorIndex": 42,
  "header": 16384,
  "literals": [
    {"type": "symbol", "index": 15},
    {"type": "compiledMethod", "localId": "method:5678"}, // Block reference
    {"type": "association", "association": {...}}
  ],
  "bytecodes": [144, 32, 124] // Standard Blue Book bytecodes
}
```

### Literal Value Types

The schema supports comprehensive literal types for method and init expression literals:

- **Primitive Values**: `symbol`, `string`, `smallInt`, `float`, `nil`, `true`, `false`
- **Object References**: `objectRef`, `compiledMethod` (blocks)
- **Complex Types**: `character`, `bytes`, `association`, `array`

## Bootstrap Process

### Overview

The cold start bootstrap creates a complete Smalltalk object memory through a carefully orchestrated 10-phase process. Each phase has specific responsibilities and builds upon previous phases.

### Bootstrap Triangle

The bootstrap process must solve a fundamental circular dependency:

```
    Classes
   ╱        ╲
  ╱          ╲
Methods ──── Objects
```

- **Classes** define the structure of objects
- **Objects** are instances of classes  
- **Methods** are objects that belong to classes

**Solution**: The bootstrap process uses placeholder objects and multi-phase wiring to resolve all circular dependencies.

### Bootstrap Result

After successful completion:
- ✅ **Object Count**: 10,821 total objects allocated
- ✅ **GC Verification**: Zero objects collected (100% reachability)
- ✅ **Class Hierarchy**: 474 classes with complete metaclass wiring
- ✅ **Method Installation**: 10,059 methods installed in class method dictionaries
- ✅ **Symbol Table**: 3,914 symbols in Universal Symbol Table
- ✅ **Special Objects**: All special objects properly configured as GC roots

## 10-Phase Implementation

### Phase 0: Preflight Validation
**Purpose**: Validate JSON bundle structure and metadata consistency  
**Heap Manager Usage**: None - pure validation  
**Key Operations**:
- Schema compliance checking
- Metadata count verification
- Cross-reference validation

### Phase 1: Symbol Interning
**Purpose**: Create all Symbol objects and build SymbolRegistry  
**Heap Manager Usage**: `AllocateObject`, `SetIndexedByte`  
**Key Operations**:
```csharp
// Look up Symbol class layout from bundle
var symbolClassDefinition = FindClassDefinition("Symbol");

// Allocate ByteIndexed object for symbol text
var symbolOOP = _heapManager.AllocateObject(
    classOOP: placeholderClassOOP,
    format: ObjectFormat.ByteIndexed,
    instanceVariableCount: symbolClassDefinition.InstVarNames.Length,
    indexedSize: symbolBytes.Length
);

// Store UTF-8 encoded text
for (int i = 0; i < symbolBytes.Length; i++)
{
    _heapManager.SetIndexedByte(symbolOOP, i, symbolBytes[i]);
}
```

### Phase 2: Class Shells
**Purpose**: Allocate placeholder Class objects for all classes  
**Heap Manager Usage**: `AllocateObject`, `SetInstanceVariable`, `SetIndexedOOP`  
**Key Operations**:
- Create SystemDictionary with exact size calculation
- Allocate Class objects using Class class layout
- Register instance classes in GlobalRegistry
- Create class name associations for SystemDictionary

### Phase 3: Metaclass Wiring  
**Purpose**: Establish the metaclass hierarchy and fundamental relationships  
**Heap Manager Usage**: `SetInstanceVariable` with named slot mapping  
**Key Operations**:
- Wire fundamental metaclass circle (meta:Object → class:Class → class:ClassDescription → class:Object)
- Compute all 236 metaclass superclass relationships
- Set class/metaclass bidirectional links

### Phase 4: Class Resolution
**Purpose**: Populate class objects with names, superclasses, and metadata  
**Heap Manager Usage**: `SetInstanceVariable`, bundle-based slot resolution  
**Key Operations**:
```csharp
private void SetNamedSlot(int objectId, string slotName, int valueId)
{
    var classDefinition = FindClassDefinitionForObject(objectId);
    int index = FindInstanceVariableIndex(classDefinition, slotName);
    _heapManager.SetInstanceVariable(objectOOP, index, valueOOP);
}
```

### Phase 5: Layout Computation
**Purpose**: Build layout resolver for object allocation  
**Heap Manager Usage**: None - pure computation  
**Key Operations**: Compute class layouts and inheritance chains

### Phase 6: Object Allocation
**Purpose**: Allocate all objects from JSON bundle  
**Heap Manager Usage**: All allocation methods, format-specific access  
**Key Operations**:
- Allocate nil, true, false singletons with correct class layouts
- Process all objects with proper format determination
- Handle complex field types (floats, characters, byte arrays)

### Phase 7: Method Installation
**Purpose**: Create CompiledMethod objects and install in class method dictionaries  
**Heap Manager Usage**: `AllocateObject` (CompiledMethod format), literal handling  
**Key Operations**:
```csharp
// Build blockOwnerMap for runtime block resolution
var blockOwnerMap = new Dictionary<string, string>();
foreach (var method in _bundle.Methods)
{
    foreach (var literal in method.Literals)
    {
        if (literal.Type == "compiledMethod")
        {
            blockOwnerMap[literal.LocalId] = method.LocalId;
        }
    }
}
GlobalRegistry.Set("blockOwnerMap", blockOwnerMap);

// Create CompiledMethod with PointerIndexed layout
// Layout: [header] [literal1] [literal2] ... [literalN] [bytecodeArrayOOP]
var methodOOP = _heapManager.AllocateObject(
    placeholderClassOOP, ObjectFormat.PointerIndexed,
    compiledMethodClassDefinition.InstVarNames.Length, 
    1 + literalIds.Length + 1  // header + literals + bytecode array reference
);
```

### Phase 8: Patch Application
**Purpose**: Apply post-allocation patches for circular references  
**Heap Manager Usage**: `SetInstanceVariable`, `SetIndexedOOP`  
**Key Operations**:
- Resolve forward references
- Set association values
- Add late objects to SystemDictionary

### Phase 9: Init Expression Preparation
**Purpose**: Create method objects for initialization expressions  
**Heap Manager Usage**: Same as method installation  
**Key Operations**:
- Create CompiledMethod objects for each init expression
- Resolve literals with existing object references
- Return array for temporary GC root storage

### Phase 10: USTable Population
**Purpose**: Create and populate Universal Symbol Table  
**Heap Manager Usage**: `AllocateObject`, `SetIndexedOOP`  
**Key Operations**:
```csharp
// Create USTable as Array with proper size
var ustableOOP = _heapManager.AllocateObject(
    placeholderClassOOP, ObjectFormat.PointerIndexed,
    arrayClassDefinition.InstVarNames.Length, ustableSize
);

// Insert symbols using hash-based open addressing
foreach (var (index, symbolId) in symbolObjects)
{
    string symbolName = _bundle.Symbols[index];
    int hash = SymbolHasher.ComputeHash(symbolName);
    InsertIntoUSTable(ustableId, symbolId, hash);
}
```

### Phase Integration Points

Each phase uses helper methods that eliminate hardcoded assumptions:

```csharp
// Bundle-based class layout resolution
private ClassDescriptor? FindClassDefinition(string className)
{
    return _bundle.Classes.FirstOrDefault(c => 
        !c.IsMetaclass && _bundle.Symbols[c.NameIndex] == className);
}

// Instance variable index mapping
private int FindInstanceVariableIndex(ClassDescriptor classDefinition, string variableName)
{
    for (int i = 0; i < classDefinition.InstVarNames.Length; i++)
    {
        string varName = _bundle.Symbols[classDefinition.InstVarNames[i]];
        if (varName == variableName) return i;
    }
    return -1;
}

// Format-aware object allocation
private int AllocateObject(string className, string formatHint, int fixedSize, int indexedSize)
{
    ObjectFormat format = formatHint.ToLower() switch
    {
        "pointers" => ObjectFormat.Pointer,
        "pointerindexed" => ObjectFormat.PointerIndexed,
        "bytes" => ObjectFormat.ByteIndexed,
        "words" => ObjectFormat.WordIndexed,
        "compiledmethod" => ObjectFormat.PointerIndexed,  // CompiledMethod uses PointerIndexed
        _ => ObjectFormat.Pointer
    };
    
    var objectOOP = _heapManager.AllocateObject(placeholderClassOOP, format, fixedSize, indexedSize);
    return objectOOP.AsObjectTableIndex();
}
```

## BlockContext Support

### v1.0.3 Block Implementation Strategy

**Core Principle**: Blocks are separate CompiledMethod objects, not inline bytecode constructs.

#### Block Ownership Resolution

During Phase 7 (Method Installation), the cold start builds a comprehensive block ownership map:

```csharp
// Build blockOwnerMap by scanning all method literals
var blockOwnerMap = new Dictionary<string, string>(); // blockLocalId -> ownerMethodOrBlockLocalId

foreach (var method in _bundle.Methods)
{
    string ownerLocalId = method.LocalId;
    
    foreach (var literal in method.Literals)
    {
        if (literal.Type == "compiledMethod" && !string.IsNullOrEmpty(literal.LocalId))
        {
            // This method contains a block as a literal - record ownership
            blockOwnerMap[literal.LocalId] = ownerLocalId;
        }
    }
}

// Store for runtime access
GlobalRegistry.Set("blockOwnerMap", blockOwnerMap);
```

#### BlockContext Structure

BlockContext objects contain 5 fixed fields plus indexed fields for arguments and temporaries:

- **Fixed Fields**: [method, initialIP, blockArgumentCount, homeContext, outerContext]
- **Indexed Fields**: [arg0..argN, temp0..tempM] (initialized to nil)

#### Runtime Block Invocation

When the VM encounters `value`/`value:`/`value:value:` messages sent to CompiledMethod receivers:

1. **Owner Resolution**: Look up block owner from blockOwnerMap
2. **Home Context**: Determine homeContext (current active MethodContext)
3. **BlockContext Creation**: Allocate BlockContext with proper parameters
4. **Argument Binding**: Store arguments in BlockContext.IndexedFields
5. **Execution**: Create MethodContext backed by BlockContext and execute

#### Init Expression Context Creation

Init expressions need proper MethodContext creation before execution:

```csharp
// Create MethodContext for init expression
var methodContext = CreateMethodContext(
    receiver: classObject,           // For class-side methods
    method: initExpressionMethod,
    homeContext: null,              // Top-level
    blockClosure: null              // Not a block
);
```

## Performance Characteristics

### Cold Start Performance

**Typical Execution Times** (on modern hardware):
- **Total Cold Start**: ~2-3 seconds
- **Phase 1 (Symbol Interning)**: ~200ms
- **Phase 7 (Method Installation)**: ~800ms (largest phase)
- **GC Verification**: ~100ms
- **Memory Usage**: ~15MB heap for 10,821 objects

### Memory Efficiency

**Object Table Growth**:
- **Block Size**: 1,024 entries per block
- **Growth Strategy**: Allocate new blocks as needed
- **Memory Overhead**: ~4 bytes per object table entry
- **Total Capacity**: Scales to millions of objects

**Tagged OOP Benefits**:
- **SmallInteger Storage**: No heap allocation for integers
- **Cache Efficiency**: 32-bit OOPs fit in CPU cache lines
- **Memory Savings**: ~40% reduction vs. boxed integers

### Garbage Collection Performance

**Mark-and-Sweep Characteristics**:
- **Mark Phase**: O(reachable objects) with recursive marking
- **Sweep Phase**: O(total objects) linear scan
- **Collection Rate**: Typically 0 objects during cold start
- **Statistics**: Comprehensive timing and breakdown data
