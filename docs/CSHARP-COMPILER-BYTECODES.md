# C# Smalltalk Compiler Bytecode Reference

This document comprehensively documents all bytecode opcodes generated by the C# Smalltalk-80 offline compiler (`Smalltalk80.Compiler` project). The compiler generates Blue Book compliant bytecodes in the range 0x00-0xFF.

## Detailed Bytecode Descriptions

### Push Operations (0x00-0x5F)

#### 0x00-0x0F: Push Receiver Instance Variable
- **Mnemonic**: `PUSH_IVAR_0` to `PUSH_IVAR_15`
- **Semantics**: Push the value of receiver's instance variable at index 0-15
- **Stack Effect**: → value
- **Usage**: Accessing instance variables in methods
- **Example**: `self instVarAt: n` generates `PUSH_IVAR_n`

#### 0x10-0x1F: Push Temporary Location
- **Mnemonic**: `PUSH_TEMP_0` to `PUSH_TEMP_15`
- **Semantics**: Push value from temporary frame slot 0-15
- **Stack Effect**: → value
- **Context**: Used for method arguments, temporaries, and block variables
- **Note**: All variables (method args, temps, block args, block temps) share unified temp frame

#### 0x20-0x3F: Push Literal Constant
- **Mnemonic**: `PUSH_LITERAL_CONST_0` to `PUSH_LITERAL_CONST_31`
- **Semantics**: Push literal at index 0-31 from method's literal frame
- **Stack Effect**: → literal
- **Literals**: Numbers, strings, symbols, arrays, characters, floats
- **Special**: Symbol literals forced into otherLiterals (not selectors list)

#### 0x40-0x5F: Push Literal Variable
- **Mnemonic**: `PUSH_LITERAL_VAR_0` to `PUSH_LITERAL_VAR_31`
- **Semantics**: Push the VALUE of the Association/GlobalVariable/PoolVariable at index 0-31
- **Stack Effect**: → value
- **Usage**: Accessing global variables, class variables, pool variables
- **Note**: The literal frame contains the Association object, bytecode pushes its value

### Store Operations (0x60-0x6F)

#### 0x60-0x67: Pop and Store Receiver Variable
- **Mnemonic**: `POP_STORE_IVAR_0` to `POP_STORE_IVAR_7`
- **Semantics**: Pop stack top and store into receiver's instance variable 0-7
- **Stack Effect**: value →
- **Usage**: Instance variable assignment

#### 0x68-0x6F: Pop and Store Temporary
- **Mnemonic**: `POP_STORE_TEMP_0` to `POP_STORE_TEMP_7`
- **Semantics**: Pop stack top and store into temporary frame slot 0-7
- **Stack Effect**: value →
- **Usage**: Local variable assignment, block argument initialization

### Special Constants (0x70-0x77)

#### 0x70: Push Receiver (self)
- **Mnemonic**: `PUSH_SELF`
- **Semantics**: Push the receiver object
- **Stack Effect**: → receiver
- **Note**: Also used for super (super uses self as receiver)

#### 0x71: Push True
- **Mnemonic**: `PUSH_TRUE`
- **Semantics**: Push the true singleton
- **Stack Effect**: → true

#### 0x72: Push False
- **Mnemonic**: `PUSH_FALSE`
- **Semantics**: Push the false singleton
- **Stack Effect**: → false

#### 0x73: Push Nil
- **Mnemonic**: `PUSH_NIL`
- **Semantics**: Push the nil singleton
- **Stack Effect**: → nil

#### 0x74: Push -1
- **Mnemonic**: `PUSH_MINUS_ONE`
- **Semantics**: Push SmallInteger -1
- **Stack Effect**: → -1

#### 0x75: Push 0
- **Mnemonic**: `PUSH_ZERO`
- **Semantics**: Push SmallInteger 0
- **Stack Effect**: → 0

#### 0x76: Push 1
- **Mnemonic**: `PUSH_ONE`
- **Semantics**: Push SmallInteger 1
- **Stack Effect**: → 1

#### 0x77: Push 2
- **Mnemonic**: `PUSH_TWO`
- **Semantics**: Push SmallInteger 2
- **Stack Effect**: → 2

### Return Operations (0x78-0x7F)

#### 0x78: Return Receiver
- **Mnemonic**: `RETURN_SELF`
- **Semantics**: Return receiver to sender
- **Usage**: Methods with no explicit return

#### 0x79: Return True
- **Mnemonic**: `RETURN_TRUE`
- **Semantics**: Return true singleton to sender

#### 0x7A: Return False
- **Mnemonic**: `RETURN_FALSE`
- **Semantics**: Return false singleton to sender

#### 0x7B: Return Nil
- **Mnemonic**: `RETURN_NIL`
- **Semantics**: Return nil to sender

#### 0x7C: Return Top
- **Mnemonic**: `RETURN_TOP`
- **Semantics**: Pop stack top and return it to sender
- **Stack Effect**: value →
- **Usage**: Normal method returns, implicit block returns

#### 0x7D: Return Receiver from Block
- **Mnemonic**: `RETURN_SELF_POP`
- **Semantics**: Return receiver from block context (non-local)
- **Note**: Not currently used by compiler

#### 0x7E: Return Top from Block
- **Mnemonic**: `RETURN_TOP_POP`
- **Semantics**: Non-local return from block (^expression)
- **Stack Effect**: value →
- **Usage**: Explicit block returns with ^

#### 0x7F: Reserved
- **Mnemonic**: `RESERVED_RETURN`
- **Semantics**: NOP (no operation)

### Blue Book Extended Operations (0x80-0x86)

The C# compiler now generates Blue Book compliant extended bytecodes.

#### 0x80: Extended Push
- **Format**: `0x80 <type:index>`
- **Extension byte**: `ttiiiii` where `tt` = type (0-3), `iiiiii` = index (0-63)
- **Types**: 00=receiver variable, 01=temporary, 10=literal constant, 11=literal variable
- **Stack Effect**: → value
- **Usage**: Push variables/literals with index > standard bytecode range (16/32)

#### 0x81: Extended Store (no pop)
- **Format**: `0x81 <type:index>`
- **Extension byte**: Same format as 0x80
- **Types**: 00=receiver variable, 01=temporary, 11=literal variable (10 illegal)
- **Stack Effect**: value → value (leaves value on stack)
- **Usage**: Store without popping (for cascades)

#### 0x82: Extended Pop and Store
- **Format**: `0x82 <type:index>`
- **Extension byte**: Same format as 0x80
- **Types**: 00=receiver variable, 01=temporary, 11=literal variable (10 illegal)
- **Stack Effect**: value →
- **Usage**: Store variables with index > 7

#### 0x83: Single Extended Send
- **Format**: `0x83 <nnnlllll>`
- **Extension byte**: `nnnlllll` where `nnn` = argCount (0-7), `lllll` = literalIndex (0-31)
- **Stack Effect**: receiver, args... → result
- **Usage**: Send with argCount > 2 or literalIndex > 15

#### 0x84: Double Extended Send
- **Format**: `0x84 <argCount> <literalIndex>`
- **Two extension bytes**: first = argCount, second = literalIndex
- **Stack Effect**: receiver, args... → result
- **Usage**: Send with argCount > 7 or literalIndex > 31

#### 0x85: Single Extended Super Send
- **Format**: `0x85 <nnnlllll>`
- **Extension byte**: Same format as 0x83
- **Stack Effect**: receiver, args... → result
- **Usage**: Super send with argCount ≤ 7 and literalIndex ≤ 31

#### 0x86: Double Extended Super Send
- **Format**: `0x86 <argCount> <literalIndex>`
- **Two extension bytes**: Same format as 0x84
- **Stack Effect**: receiver, args... → result
- **Usage**: Super send with argCount > 7 or literalIndex > 31

### Stack Operations (0x87-0x88)

#### 0x87: Pop
- **Mnemonic**: `POP`
- **Semantics**: Pop and discard top of stack
- **Stack Effect**: value →
- **Usage**: Discard unused expression results

#### 0x88: Duplicate
- **Mnemonic**: `DUP`
- **Semantics**: Duplicate top of stack
- **Stack Effect**: value → value, value
- **Usage**: Cascade expressions

### Context Operations

#### 0x89: Push Active Context
- **Mnemonic**: `PUSH_ACTIVE_CONTEXT`
- **Semantics**: Push the current execution context (thisContext)
- **Stack Effect**: → context
- **Usage**: Used before blockCopy: for block compilation
- **Note**: Essential for reflection and block creation

### Jump Operations (0x90-0xAF)

#### 0x90-0x97: Short Unconditional Jump
- **Format**: Single byte
- **Semantics**: Jump forward by (bytecode & 0x07) + 1 bytes (1-8)
- **Stack Effect**: (none)
- **Usage**: Short forward jumps in control flow

#### 0x98-0x9F: Short Conditional Jump on False
- **Format**: Single byte
- **Semantics**: Pop top, jump forward by (bytecode & 0x07) + 1 bytes if false
- **Stack Effect**: boolean →
- **Usage**: ifFalse: optimization (when enabled)

#### 0xA0-0xA7: Long Unconditional Jump
- **Format**: `0xA0-0xA7 <offset>`
- **Semantics**: Jump by ((bytecode & 0x07) - 4) * 256 + nextByte
- **Range**: -1024 to +1023 (backward and forward jumps)
- **Stack Effect**: (none)
- **Usage**: Long jumps, tail recursion (backward jumps)

#### 0xA8-0xAB: Long Conditional Jump on True
- **Format**: `0xA8-0xAB <offset>`
- **Semantics**: Pop top, jump forward by (bytecode & 0x03) * 256 + nextByte if true
- **Range**: 0-1023 (forward only)
- **Stack Effect**: boolean →
- **Usage**: ifTrue: optimization (when enabled)

#### 0xAC-0xAF: Long Conditional Jump on False
- **Format**: `0xAC-0xAF <offset>`
- **Semantics**: Pop top, jump forward by (bytecode & 0x03) * 256 + nextByte if false
- **Range**: 0-1023 (forward only)
- **Stack Effect**: boolean →
- **Usage**: ifFalse: optimization (when enabled)

### Send Operations (0xB0-0xFF)

#### 0xB0-0xBF: Send Arithmetic Selector
Special bytecodes for common arithmetic operations:
- **0xB0**: `+` (1 arg)
- **0xB1**: `-` (1 arg)
- **0xB2**: `<` (1 arg)
- **0xB3**: `>` (1 arg)
- **0xB4**: `<=` (1 arg)
- **0xB5**: `>=` (1 arg)
- **0xB6**: `=` (1 arg)
- **0xB7**: `~=` (1 arg)
- **0xB8**: `*` (1 arg)
- **0xB9**: `/` (1 arg)
- **0xBA**: `\\` (mod, 1 arg)
- **0xBB**: `@` (1 arg)
- **0xBC**: `bitShift:` (1 arg)
- **0xBD**: `//` (integer divide, 1 arg)
- **0xBE**: `bitAnd:` (1 arg)
- **0xBF**: `bitOr:` (1 arg)

#### 0xC0-0xCF: Send Special Selector
Special bytecodes for common selectors:
- **0xC0**: `at:` (1 arg)
- **0xC1**: `at:put:` (2 args)
- **0xC2**: `size` (0 args)
- **0xC3**: `next` (0 args)
- **0xC4**: `nextPut:` (1 arg)
- **0xC5**: `atEnd` (0 args)
- **0xC6**: `==` (1 arg)
- **0xC7**: `class` (0 args)
- **0xC8**: `blockCopy:` (1 arg) - **Special handling for block creation**
- **0xC9**: `value` (0 args)
- **0xCA**: `value:` (1 arg)
- **0xCB**: `do:` (1 arg)
- **0xCC**: `new` (0 args)
- **0xCD**: `new:` (1 arg)
- **0xCE**: `x` (0 args)
- **0xCF**: `y` (0 args)

#### 0xD0-0xDF: Send Literal Selector with 0 Arguments
- **Format**: `0xD0 + index` (single byte)
- **Semantics**: Send selector at literal frame index 0-15 with no arguments
- **Stack Effect**: receiver → result

#### 0xE0-0xEF: Send Literal Selector with 1 Argument
- **Format**: `0xE0 + index` (single byte)
- **Semantics**: Send selector at index 0-15 with 1 argument
- **Stack Effect**: receiver, arg → result

#### 0xF0-0xFF: Send Literal Selector with 2 Arguments
- **Format**: `0xF0 + index` (single byte)
- **Semantics**: Send selector at index 0-15 with 2 arguments
- **Stack Effect**: receiver, arg1, arg2 → result

## Block Compilation Pattern

The compiler generates blocks inline using this pattern:

```
PUSH_ACTIVE_CONTEXT      ; 0x89 - Push thisContext for blockCopy:
PUSH_SMALL_INT argCount  ; Push block argument count
SEND_SPECIAL_BLOCKCOPY   ; 0xC8 - Create BlockContext
LONG_JUMP_FORWARD offset ; 0xA1 XX XX - Skip block body
<block body starts here> ; initialIP points here
POP_STORE_TEMP args...   ; Store block arguments from stack to temps
<block statements>       ; Block code
RETURN_TOP               ; 0x7C - Local return from block
<jump lands here>        ; Method execution continues
```

## Literal Frame Organization

The compiler organizes literals for optimal bytecode encoding:
1. **Selectors** (indices 0-N): Message selectors placed first
2. **Other literals** (indices N+1...): Constants, variables, arrays

This allows common selectors to use single-byte send opcodes (0xD0-0xFF).

## Variable Resolution

The compiler resolves variables in this priority order:
1. **Pseudo-variables**: self, super, true, false, nil, thisContext
2. **Method arguments**: Stored in temp frame slots 0..argCount-1
3. **Method temporaries**: Stored after arguments
4. **Block arguments**: Stored in unified temp frame
5. **Block temporaries**: Stored after block arguments
6. **Instance variables**: Via PUSH_IVAR/POP_STORE_IVAR
7. **Class variables**: Via literal associations
8. **Pool variables**: Via literal associations with pool name
9. **Global variables**: Via literal associations (undeclared tracked)

## Optimization Features

### Tail Recursion Optimization
When enabled (`OptimizeTailRecursion` option), the compiler transforms:
- Tail-recursive calls into backward jumps (0xA8)
- Updates arguments in-place via STORE_TEMP
- Avoids MethodContext creation overhead
- Limited to methods < 256 bytes due to jump offset constraint

### Special Selector Optimization
The compiler automatically uses special bytecodes for:
- Common arithmetic operations (0xB0-0xBF)
- Frequently used selectors (0xC0-0xCF)
- This reduces literal frame usage and bytecode size

### Conditional Optimization (ENABLED)
The compiler inlines `ifTrue:`, `ifFalse:`, `ifTrue:ifFalse:`, `ifFalse:ifTrue:`, `and:`, and `or:`:
- These control structures use conditional jump bytecodes (0x98-0x9F, 0xA8-0xAF)
- Zero-argument blocks are compiled inline (no BlockContext created)
- Supports both "for value" and "for effect" compilation patterns:
  - **For value**: `<cond> BFP <block> JMP PUSH_NIL` - leaves nil when condition false
  - **For effect**: `<cond> BFP <block>` - shortcut pattern, nothing on stack
- Two-arm conditionals (`ifTrue:ifFalse:`) always leave a value on stack
- Note: `whileTrue:` and `whileFalse:` are NOT yet inlined (receiver is a block)

## Implementation Notes

### Unified Temp Frame
All variables (method args, temps, block args, block temps) are allocated in the MethodContext's unified temp frame:
- Compiler uses `TempFrameAllocator` for slot management
- Block variables use absolute indices via home pointer traversal
- Enables slot reuse for sequential (non-nested) blocks

### Block Argument Handling
Block arguments are handled via Blue Book pattern:
- Primitive 81 pushes arguments onto BlockContext stack
- Compiler emits POP_STORE_TEMP bytecodes to move them to slots
- Handles non-contiguous mappings when names shadow method variables

### Super Send Implementation
Super sends always use extended bytecodes (0x80 0x0E-0x11):
- Cannot use special selector bytecodes
- Selector pre-added to literal frame before compiling arguments
- Ensures correct literal indexing

### Source Position Tracking
The compiler can embed source file positions in bytecode:
- Last 3 bytes of method bytecode can encode position
- Used for source code retrieval in development tools
- Format: position encoded as 3-byte integer

## Bytecode Validation

The compiler includes bytecode analysis for:
- **Stack depth calculation**: Via `CalculateMaxStackDepth()`
- **Jump offset validation**: Ensures jumps within bounds
- **Literal index validation**: Checks indices within frame size
- **Variable resolution tracking**: Records undeclared variables
