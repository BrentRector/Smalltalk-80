## Overview

### What is Cold Start?

Cold start is the process of bootstrapping a Smalltalk-80 virtual machine from a serialized JSON representation of the entire Smalltalk image. The process transforms static JSON data into a living, executable object graph in memory.

### Key Challenges

1. **Circular Dependencies**: Classes need metaclasses, metaclasses need classes, all need nil
2. **Ordering Constraints**: Symbols must exist before classes that reference them
3. **Memory Safety**: Object references must be valid before use
4. **Semantic Correctness**: Must maintain Smalltalk-80 Blue Book semantics

### Overall Flow

```
JSON Bundle → Parse → 15 Sequential Phases → Live Smalltalk Heap → Runtime Execution
```

**Total Objects Created**: ~30,000 objects
**Total Time**: ~500-1000ms
**Success Criteria**: All objects allocated, fully initialized, and reachable from GC roots

## JSON Input Format

### Bundle Structure

The `coldstart.json` file contains a complete serialization of the Smalltalk-80 system. It is generated by the Smalltalk-80 compiler from the canonical `.st` source file.

```json
{
  "version": "1.0.5",
  "symbols": ["Object", "Class", "new", "at:", ...],
  "strings": ["A comment", "Some documentation", ...],
  "classes": [/* 480 class descriptors */],
  "objects": [/* 2 pre-allocated singleton objects */],
  "methods": [/* 10,182 compiled methods */],
  "initExpressions": [/* 285 initialization expressions */]
}
```

### Symbols Array

**Purpose**: Deduplicated symbol table for all symbolic names in the system.

**Format**:
```json
"symbols": [
  "Object",           // index 0
  "Class",            // index 1
  "superclass",       // index 2
  "new",              // index 3
  ...
]
```

**Characteristics**:
- Index-based references (not string values)
- Globally unique (one symbol per unique string)
- Used for: class names, method selectors, instance variable names, symbols in code

**Size**: 3,834 symbols in standard Smalltalk-80 image

---

### Strings Array

**Purpose**: String literals appearing in method code and class comments.

**Format**:
```json
"strings": [
  "This is the root of the class hierarchy",  // index 0
  "Point represents an x,y coordinate pair",  // index 1
  ...
]
```

**Characteristics**:
- NOT deduplicated (each occurrence is separate)
- Used for: comments, string literals in code, error messages
- Encoded as UTF-8

**Size**: Varies, typically thousands of strings

---

### Classes Array

**Purpose**: Complete description of all 480 classes (240 regular + 240 metaclasses).

**Format**:
```json
{
  "localId": "class:Object",
  "nameIndex": 0,              // index into symbols array
  "superNameIndex": null,      // Object has no superclass
  "isMetaclass": false,
  "metaclassOfLocalId": null,
  "format": 0x4092,            // encoded: instance spec, indexed type, size
  "instVarNames": [2, 5, 8],   // indices into symbols array
  "classVarNames": [],
  "poolLocalIds": [],
  "methodLocalIds": ["method:Object>>new", "method:Object>>class", ...],
  "commentStringIndex": 0
}
```

**Key Fields**:

- **localId**: Unique identifier for this class (format: `"class:ClassName"` or `"meta:ClassName"`)
- **nameIndex**: Index into `symbols[]` for class name
- **superNameIndex**: Index into `symbols[]` for superclass name (`null` only for Object)
- **isMetaclass**: `true` for metaclasses (`meta:*`), `false` for regular classes
- **metaclassOfLocalId**: For metaclasses, the localId of the instance class (e.g., `"class:Object"` for `"meta:Object"`)
- **format**: 16-bit encoded format word (per Blue Book Chapter 27):
  - Bit 0: isPointers (1=contains pointers, 0=contains values)
  - Bit 1: isWords (1=word-addressed, 0=byte-addressed)
  - Bit 2: isIndexable (1=has indexed fields, 0=fixed size only)
  - Bit 3: reserved
  - Bits 4-14: fixedFields (number of fixed instance variables, 0-2047)
  - Bit 15: reserved
- **instVarNames**: Indices into `symbols[]` for instance variable names (in order)
- **classVarNames**: Indices into `symbols[]` for class variable names
- **poolLocalIds**: References to shared pool dictionaries
- **methodLocalIds**: References to all methods defined in this class
- **commentStringIndex**: Index into `strings[]` for class comment

**Count**: 480 classes (240 pairs: Object/meta:Object, Class/meta:Class, etc.)

---

### Objects Array

**Purpose**: Pre-allocated singleton objects that must exist before methods can execute.

**Format**:
```json
{
  "localId": "Smalltalk",
  "classNameIndex": 42,        // index into symbols[], e.g., "SystemDictionary"
  "fields": [
    {"type": "objectRef", "localId": "USTable"},
    {"type": "nil"},
    ...
  ]
}
```

**Typical Objects**:
- `Smalltalk` (SystemDictionary global)
- `ProcessorScheduler` (process scheduling singleton)

**Count**: 2 objects

---

### Methods Array

**Purpose**: All compiled methods in the system.

**Format**:
```json
{
  "localId": "method:Object>>new",
  "classLocalId": "class:Object",
  "selector": 142,             // index into symbols[]
  "header": {
    "type": "compiledMethod",
    "word": 0x8003,            // encoded header
    "argCount": 0,
    "tempCount": 0,
    "primitiveIndex": 70,
    "literalCount": 1
  },
  "literals": [
    {"type": "symbol", "index": 142}  // selector
  ],
  "bytecodes": "base64EncodedBytecodeString"
}
```

**Header Word Encoding** (16 bits):
- Bits 0-4: Argument count (0-31)
- Bits 5-9: Temporary variable count (0-31)
- Bit 10: Large context flag
- Bits 11-14: Literal count (0-15)
- Bit 15: Primitive flag

**Literal Types**:
- `symbol`: Index into symbols array
- `string`: Index into strings array
- `smallInt`: Immediate integer value
- `float`: IEEE 754 double
- `nil`, `true`, `false`: Singleton references
- `objectRef`: Reference to another object by localId
- `compiledMethod`: Reference to another method (for block closures)
- `character`: Unicode code point
- `bytes`: Byte array (base64 encoded)
- `association`: Key-value pair (for globals)
- `array`: Array of literal values

**Count**: 10,182 methods

---

### Init Expressions Array

**Purpose**: DoIt expressions that execute during startup to initialize the system.

**Format**:
```json
{
  "localId": "init:001",
  "source": "Object comment: 'Root of class hierarchy'",
  "header": {"type": "compiledMethod", "word": 0x8001, ...},
  "literals": [{"type": "objectRef", "localId": "class:Object"}, ...],
  "bytecodes": "base64EncodedBytecodeString"
}
```

**Execution**:
- Compiled as methods with `nil` receiver (actually uses `Smalltalk` global)
- Execute after cold start completes
- Used for: setting class comments, initializing class variables, creating initial objects

**Count**: 285 init expressions

## Desired Output State

### Memory Layout

After cold start completes, the heap contains approximately 30,000 objects organized as:

```
┌─────────────────────────────────────────┐
│         Object Table (Blocks)           │
│  - 30,000 entries (15 blocks × 2048)    │
│  - Each entry: class, format, storage   │
└─────────────────────────────────────────┘
          ↓
┌─────────────────────────────────────────┐
│         Object Storage (Managed)        │
│  - Byte arrays (strings, bytecodes)     │
│  - OOP arrays (objects, methods)        │
│  - SmallInteger (immediate values)      │
└─────────────────────────────────────────┐
```

### Object Graph Structure

The complete object graph must satisfy these invariants:

#### 1. **All Objects Have Valid Class References**

Every object's slot 0 must contain a valid class OOP:
```
object.slots[0] = classOOP (never null/0)
```

**Exception**: SmallIntegers don't have slots (immediate values)

#### 2. **Fundamental Metaclass Circle**

The metaclass hierarchy forms a precise circle:
```
meta:Object.superclass = class:Class
class:Class.superclass = class:ClassDescription
class:ClassDescription.superclass = class:Behavior
class:Behavior.superclass = class:Object
```

This allows class-side methods like `new` to be inherited by all classes.

#### 3. **Regular Class Hierarchy**

All regular classes form a tree rooted at Object:
```
Object.superclass = nil
  ├─ Behavior.superclass = Object
  │   ├─ ClassDescription.superclass = Behavior
  │   │   ├─ Class.superclass = ClassDescription
  │   │   └─ Metaclass.superclass = ClassDescription
  │   └─ ...
  ├─ Collection.superclass = Object
  │   ├─ SequenceableCollection.superclass = Collection
  │   └─ ...
  └─ ...
```

#### 4. **All Metaclasses Wired Correctly**

For every class `Foo`:
```
meta:Foo.superclass = meta:Bar  (where Bar = Foo.superclass)
```

**Exception**: `meta:Object.superclass = class:Class` (fundamental circle)

#### 5. **Method Dictionaries Installed**

Every class and metaclass must have:
```
class.methodDict = Dictionary instance
  - Contains selector → CompiledMethod associations
  - Correctly sized (based on method count)
  - All methods installed
```

#### 6. **Symbols Interned in USTable**

The Universal Symbol Table must contain all 3,834 symbols:
```
USTable (Array) = [symbol1, symbol2, ..., symbol3834]
  - Each entry is a Symbol object (ByteIndexed, subclass of String)
  - Globally accessible via Smalltalk.symbols
```

#### 7. **Global Variables in Smalltalk Dictionary**

The `Smalltalk` global (SystemDictionary) must contain:
```
Smalltalk at: #Object put: class:Object
Smalltalk at: #Class put: class:Class
Smalltalk at: #Smalltalk put: Smalltalk (self-reference)
... (all 240+ classes)
```

#### 8. **Special Objects Array (GC Roots)**

Must contain exactly 5-6 roots:
```
[nil, false, true, Smalltalk, ProcessorScheduler, InitExpressionMethods]
```

These are the ONLY GC roots. All other objects must be reachable from these.

#### 9. **CompiledMethods Fully Initialized**

Each CompiledMethod must have:
```
- Header (SmallInteger encoding arg/temp/literal counts)
- Literals array (OOPs to symbols, strings, objects)
- Bytecode array (separate ByteArray object)
- Class reference = class:CompiledMethod
```

#### 10. **All Instance Variables Initialized**

Every instance variable in every object must be:
- Either explicitly set to a meaningful value, OR
- Initialized to `nil`

**Never**: `null`, `0`, uninitialized, or invalid OOP

## Phase-by-Phase Execution

### Execution Order

```
Phase 0:  Preflight Validation
Phase 1:  Symbol Interning
Phase 2:  Class Shells
Phase 3:  Metaclass Wiring
Phase 4:  Class Resolution
Phase 5:  Layout Computation
Phase 6:  Object Allocation (creates nil/true/false)
Phase X:  Class Reference Initialization
Phase Y:  Instance Variable Initialization
Phase 7:  Method Dictionary Allocation
Phase 8:  Method Installation
Phase 8b: Init Expression Method Creation
Phase 9:  Method Dictionary Installation
Phase 10: Patch Application
Phase 11: Init Expression Preparation
Phase 12: USTable Population
Phase 13: Global Variable Installation
Phase 14: GC Root Setup
Phase 15: GC Verification
```

**Key Insight**: Phases 0-5 create object shells. Phase 6 creates fundamental singletons. Phases X-Y initialize references. Phases 7-15 populate behavior and validate.

---


### Phase 0: Preflight Validation

**Purpose**: Verify JSON bundle integrity before attempting cold start.

**Input State**:
- Parsed JSON bundle in memory
- No heap objects allocated yet

**Operations**:

1. **Validate Bundle Version**
   ```csharp
   if (bundle.Version != "1.0.5")
       throw new InvalidOperationException("Unsupported bundle version");
   ```

2. **Validate Array Integrity**
   - Symbols array exists and non-empty
   - Classes array contains exactly 480 entries (240 pairs)
   - Methods array exists
   - All arrays properly deserialized

3. **Validate Class Pairs**
   - For each class `Foo`, verify metaclass `meta:Foo` exists
   - For each metaclass `meta:Foo`, verify `metaclassOfLocalId = "class:Foo"`
   - Count: 240 regular classes + 240 metaclasses = 480 total

4. **Validate Critical Classes Exist**
   ```
   Required classes:
   - Object (root of hierarchy)
   - Class (template for all class objects)
   - Metaclass (template for all metaclass objects)
   - Behavior, ClassDescription (fundamental hierarchy)
   - CompiledMethod (for method storage)
   - Symbol, String (for text)
   - Array, ByteArray (for collections)
   - SmallInteger (virtual, no descriptor needed)
   ```

5. **Validate Symbol Index References**
   - All `nameIndex`, `superNameIndex`, `instVarNames[]` values < symbols.length
   - No negative indices
   - No out-of-bounds references

6. **Validate LocalId Uniqueness**
   - No duplicate `localId` values across classes, methods, objects
   - All localIds follow format: `"class:Name"`, `"meta:Name"`, `"method:Class>>selector"`, `"init:NNN"`

**Output State**:
- Bundle validated as consistent
- No heap modifications yet

**Failure Handling**:
- Throw exception immediately
- Do not proceed to Phase 1
- Print diagnostic information about what failed

**Performance**: < 10ms (JSON validation only)

**Optimizations**:
- Could cache validation results to skip on subsequent starts
- Could validate in parallel (symbols, classes, methods independently)
- Could use checksums instead of full validation

### Phase 1: Symbol Interning

**Purpose**: Allocate all Symbol objects and populate the symbol table.

**Why First**: Symbols are referenced by classes (names, selectors) and methods (selectors, variable names). Must exist before anything else.

**Input State**:
- Validated JSON bundle
- Empty heap
- Empty SymbolRegistry

**Operations**:

1. **Allocate Symbol Objects**
   ```csharp
   for (int i = 0; i < bundle.Symbols.Length; i++)
   {
       string symbolText = bundle.Symbols[i];
       byte[] utf8Bytes = Encoding.UTF8.GetBytes(symbolText);

       // Symbol is ByteIndexed (subclass of String)
       SmalltalkOOP symbolOOP = heapManager.AllocateObject(
           ObjectFormat.ByteIndexed,
           fixedSlots: 0,  // String has no instance variables
           indexedSize: utf8Bytes.Length
       );

       // Store bytes
       for (int j = 0; j < utf8Bytes.Length; j++)
       {
           heapManager.SetIndexedByte(symbolOOP, j, utf8Bytes[j]);
       }

       // Register in SymbolRegistry (index → OOP mapping)
       SymbolRegistry.Register(i, symbolOOP);
   }
   ```

2. **Freeze SymbolRegistry**
   ```csharp
   SymbolRegistry.Freeze();
   // After freezing, Register() will throw exceptions
   // Only GetSymbolOOP(int index) allowed
   ```

**Output State**:
- 3,834 Symbol objects allocated in heap
- Each symbol stored as UTF-8 byte array
- SymbolRegistry contains index → OOP mapping
- **Class references NOT set yet** (symbols have classOOP = 0)

**Why Class References Not Set**:
- `class:Symbol` doesn't exist yet (created in Phase 2)
- Will be set later in Phase X (Class Reference Initialization)

**Memory Usage**: ~100 KB (3,834 symbols × ~27 bytes average)

**Performance**: ~20ms

**Critical Invariant**: After Phase 1:
```
SymbolRegistry.GetSymbolOOP(i) returns valid OOP for all i in [0, 3833]
```

**Optimization Opportunities**:
- Could use string interning pool to reduce allocations
- Could allocate symbols in batch to reduce heap manager calls
- Could compress common symbol prefixes (e.g., "instance", "class")

### Phase 2: Class Shells

**Purpose**: Allocate empty class objects (shells) for all 480 classes and metaclasses.

**Why Now**: We need class OOPs to reference before we can wire relationships. Creating shells allows us to resolve circular dependencies.

**Input State**:
- Symbols allocated
- No class objects yet

**Operations**:

1. **Determine Class Object Format**
   ```csharp
   For regular classes (class:Foo):
       Template: class:Class
       Instance variables: superclass, methodDict, format, name, instanceVariables, organization, comment, classPool, sharedPools
       Format: PointerIndexed

   For metaclasses (meta:Foo):
       Template: class:Metaclass
       Instance variables: thisClass + (inherited from Class)
       Format: PointerIndexed
   ```

2. **Allocate Class Shells**
   ```csharp
   foreach (var cls in bundle.Classes)
   {
       // Determine instance variable count from template
       string templateClass = cls.IsMetaclass ? "Metaclass" : "Class";
       int instVarCount = ClassHierarchyUtils.CalculateTotalInstanceVariableCount(
           templateClass, bundle);

       // Allocate shell (no indexed size needed for class objects)
       SmalltalkOOP classOOP = heapManager.AllocateObject(
           ObjectFormat.PointerIndexed,
           instanceVarCount,
           indexedSize: 0
       );

       // Store in localId → OOP mapping
       localIdToObjectId[cls.LocalId] = classOOP;
   }
   ```

**Output State**:
- 480 class objects allocated
- All instance variable slots = 0 (uninitialized)
- `localIdToObjectId` mapping populated
- **Class references still 0** (will be set in Phase X)

**Memory Usage**: ~50 KB (480 classes × ~100 bytes each)

**Performance**: ~10ms

**Critical Invariant**:
```
For all localId in bundle.Classes:
    localIdToObjectId[localId] returns valid OOP
```

**Optimization Opportunities**:
- Could batch allocations by template type
- Could pre-calculate total heap size needed

### Phase 3: Metaclass Wiring

**Purpose**: Wire the fundamental metaclass hierarchy and set up metaclass superclass chains.

**Why Now**: Metaclasses have circular dependencies. Must be wired before regular class hierarchy.

**Input State**:
- Class shells allocated
- All instance variables = 0
- Nil doesn't exist yet

**Operations**:

**Step 1: Set `thisClass` Field**

```csharp
int thisClassIndex = FindInstanceVariableIndex("Metaclass", "thisClass");

foreach (var metaCls in bundle.Classes.Where(c => c.IsMetaclass))
{
    SmalltalkOOP metaOOP = localIdToObjectId[metaCls.LocalId];
    SmalltalkOOP instanceOOP = localIdToObjectId[metaCls.MetaclassOfLocalId];

    heapManager.SetInstanceVariable(metaOOP, thisClassIndex, instanceOOP);
    initializedFields.Add((metaOOP, thisClassIndex));
}
```

**Step 2: Wire Fundamental Metaclass Circle**

```csharp
meta:Object.superclass = class:Class
class:Class.superclass = class:ClassDescription
class:ClassDescription.superclass = class:Behavior
class:Behavior.superclass = class:Object
```

This circle allows class-side methods to be inherited by all classes.

**Step 3: Wire Regular Metaclass Superclasses**

```
Rule: meta:Foo.superclass = meta:Bar (where Bar = Foo.superclass)

Example:
  Point.superclass = Object
    → meta:Point.superclass = meta:Object
```

**Output State**:
- All 240 metaclasses have `thisClass` set
- All 240 metaclasses have `superclass` set
- Fundamental circle established
- 239 regular metaclass relationships wired
- 1 skipped (meta:Object, in fundamental circle)

**Performance**: ~5ms

**Critical Invariants**:
```
meta:Object.thisClass = class:Object
meta:Object.superclass = class:Class
class:Behavior.superclass = class:Object (closes circle)
```
