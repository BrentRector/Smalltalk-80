## Bugs Fixed

### 1. Validator Bug: SEND_N ArgCount Offset ✅

**File**: `BytecodeStackValidator.cs`
**Lines**: 420-421

**Problem**: Extended SEND_N bytecode (0x80 0x0D) has format:
```
0x80 0x0D <selector_index> <argCount>
```

The validator was reading `pc + 2` (selector index) instead of `pc + 3` (argCount), causing incorrect stack effect calculations.

**Fix**: Changed offset from `pc + 2` to `pc + 3`

**Impact**: Reduced errors from 1,512 to 1,406

---

### 2. Validator Bug: Jump Target Calculation ✅

**File**: `BytecodeStackValidator.cs`
**Lines**: 311, 327, 359, 375

**Problem**: Blue Book specification states jump distance = offset + 1, but validator was using:
```csharp
target = pc + 2 + offset;  // WRONG
```

Should be:
```csharp
target = pc + 2 + offset + 1;  // CORRECT
```

**Affected Instructions**:
- MEDIUM_JUMP (0xA0-0xA3)
- LONG_JUMP (0xA1-0xA7)
- Extended jumps (0x80 0x14-0x19)

**Fix**: Added `+ 1` to all jump target calculations

**Impact**: Reduced errors from 1,406 to **2** (99.86% improvement!)

---

### 3. Compiler Bug: Negative Radix Literals ✅

**File**: `BytecodeCompiler.cs`
**Lines**: 2156-2175

**Problem**: When handling negative number literals like `-16r100` (hexadecimal -256), the compiler used:
```csharp
if (int.TryParse(numText, out int positiveVal))  // FAILS for "16r100"
```

`int.TryParse` doesn't understand Smalltalk radix notation, so the parse failed silently, resulting in **zero bytecode generated** for the literal!

**Example**: In `SmallInteger>>digitLength`:
```smalltalk
minValue _ -16r100.
```

Generated bytecode:
```
[nothing for -16r100]
POP_STORE_TEMP_1  ← Stack underflow!
```

**Fix**: Changed to use `TryParseSmalltalkNumber()` which handles:
- Radix notation (8r377, 16rFF, etc.)
- Decimal, float, scaled decimals

**Impact**: Reduced errors from 2 to **1**

## Remaining Issue

### Explainer>>explain:for: - Complex Nested Block Bug ❌

**Error**: Stack underflow at PC 387
**Actual Problem**: PC 386 sends `ifTrue:ifFalse:` without the required 2 block arguments on stack

**Analysis**:
- Method contains deeply nested blocks (up to 4 levels)
- Main `showWhile:` block spans PC 7-264 (258 bytes)
- String concatenation at PC 364-385 generates correct bytecode
- Missing blocks for `ifTrue:ifFalse:` at PC 386

**Hypothesis**:
The compiler has a bug in bytecode generation for certain complex nested block structures. Similar to the negative radix bug, it appears to skip generating bytecode for block literals in specific contexts.

**Patterns Observed**:
1. Duplicate `ifTrue:ifFalse:` sends at PC 264 and PC 386
2. No block creation bytecode between PC 361-386
3. Concatenated string left on stack where boolean receiver expected

**Impact**: 1 method (0.02% of codebase)

## Validation System Architecture

### BytecodeStackValidator

**Algorithm**: Control Flow Graph (CFG) based worklist propagation

**Steps**:
1. **Build CFG**: Parse bytecode, identify basic blocks and control flow edges
2. **Worklist Propagation**:
   - Start at PC 0 with depth 0
   - For each PC, compute stack effect
   - Propagate depth to all successor PCs
   - Validate join points have consistent depths
3. **Validate Returns**: RETURN_TOP must have exactly 1 item on stack
4. **Report Errors**: Collect all errors (not fail-fast)

**Key Features**:
- Follows jump targets correctly
- Handles conditional and unconditional jumps
- Validates all 256 bytecode opcodes
- Accounts for Blue Book +1 offset in jump distances
- Proper handling of extended bytecodes
