# CRITICAL DISCOVERY: Block Compilation Architecture Mismatch

**Date**: 2025-11-06
**Status**: ⚠️ BLOCKER - Requires Major Offline Compiler Refactoring
**Priority**: CRITICAL

---

## Problem Statement

Our **offline C# compiler** generates block code that does NOT match what the **online Smalltalk-80 compiler** generates. This causes runtime failures when Smalltalk code tries to use blocks.

### Current (Wrong) Approach
- Offline compiler creates separate `CompiledMethod` objects for blocks
- Stores them in method's literal array
- `PUSH_LITERAL` pushes the CompiledMethod directly onto stack
- Runtime tries to send `whileTrue:` to CompiledMethod → **FAILS** (no such method)

### Actual Smalltalk-80 Approach (From Source Analysis)
- Compiler generates **inline bytecode** for blocks
- No literal array storage
- Creates `BlockContext` objects **at runtime** using `blockCopy:` primitive
- BlockContext has `whileTrue:`, `value`, etc. methods → **WORKS**

## How Smalltalk-80 Actually Compiles Blocks

### Source Code Example
```smalltalk
method: arg
    | temp |
    temp := [arg + 1].
    ^temp value
```

### Generated Bytecode (What Smalltalk Compiler Produces)
```
Method bytecode:
  ; Block creation inline
  LdThisContext (137)          ; Push current MethodContext
  PUSH 0                       ; Block has 0 arguments
  SEND #blockCopy:, 1          ; Primitive 80 creates BlockContext
  POP_STORE_TEMP 0             ; Store to 'temp'
  LONG_JUMP +6                 ; Jump over block body

  ; Block body (jumped over during creation, executed during value)
  PUSH_TEMP 0                  ; arg (from outer context!)
  PUSH 1
  SEND #+, 1
  EndRemote (125)              ; Return from block

  ; Method continues here
  PUSH_TEMP 0                  ; temp (the BlockContext)
  SEND #value, 0               ; Primitive 81 executes block
  RETURN_TOP
```

### Runtime Flow

**Step 1: Block Creation** (when method executes)
```
LdThisContext pushes: MethodContext for 'method:'
PUSH 0 pushes: SmallInteger 0
SEND #blockCopy: invokes: Primitive 80
```

**Primitive 80 (blockCopy:)** creates:
```smalltalk
BlockContext instance:
  nargs: 0
  startpc: <PC pointing to block body start>
  home: <the MethodContext where block was defined>
  indexedSlots: <empty stack>
```

**Step 2: Block Storage**
```
POP_STORE_TEMP 0 stores BlockContext in 'temp'
LONG_JUMP +6 skips over block body
```

**Step 3: Block Invocation**
```
PUSH_TEMP 0 pushes BlockContext from 'temp'
SEND #value invokes: Primitive 81
```

**Primitive 81 (value)** does:
1. Set `pc = startpc` (jump to block body)
2. Execute block bytecode
3. `PUSH_TEMP 0` reads `arg` from `home` context (lexical scope!)
4. EndRemote (125) returns result

## Blue Book Primitive Specification (Authoritative)

### Primitive 80: blockCopy: (Create BlockContext)

**Source**: Formal Specification of the Primitive Methods, lines 1144-1175

**Purpose**: Creates a new BlockContext instance when block literal is evaluated

**Receiver**: MethodContext or BlockContext (current context)
**Argument**: SmallInteger (block argument count)
**Returns**: New BlockContext object

**Object Structure Created**:
```smalltalk
BlockContext instance:
  Class: ClassBlockContextPointer
  Instance Variables (from Context hierarchy):
    sender:               (set by primitiveValue, not blockCopy)
    instructionPointer:   initialIP = currentPC + 3 (points PAST the jump)
    stackPointer:         0 (empty stack)

  BlockContext-specific fields:
    nargs:                blockArgumentCount (from argument)
    initialIP:            currentPC + 3 (saved for reset on each value)
    home:                 methodContext (lexical parent for variable access)

  Indexed slots:          empty array (size = home's size, for temp frame)
```

**Key Implementation Details**:
1. **Home context resolution**:
   - If receiver is MethodContext → home = receiver
   - If receiver is BlockContext → home = receiver's home (chain to method)
2. **initialIP calculation**: `instructionPointer + 3`
   - Current PC points to blockCopy: send bytecode
   - +3 skips over the 2-byte LONG_JUMP that follows
   - This points to the first bytecode of block body
3. **Context size**: BlockContext gets same indexed slot count as home MethodContext
4. **Stack empty**: stackPointer = 0, temps/args added by primitiveValue

### Primitive 81: value/value:/value:value: (Execute BlockContext)

**Source**: Formal Specification of the Primitive Methods, lines 1176-1204

**Purpose**: Transfers arguments to BlockContext and activates it for execution

**Receiver**: BlockContext
**Arguments**: 0-N arguments matching block's nargs
**Returns**: Does NOT return - switches active context (trampoline)

**Execution Flow**:
```smalltalk
1. Validate argument count:
   - blockArgumentCount = receiver.nargs
   - Fail if argumentCount ≠ blockArgumentCount

2. Transfer arguments from active context to block context:
   - Copy from: activeContext stack[stackPointer - argumentCount + 1 .. stackPointer]
   - Copy to: blockContext indexed slots[TempFrameStart .. TempFrameStart + argumentCount - 1]

3. Initialize block context for execution:
   - Pop arguments + receiver from active context stack
   - Set blockContext.instructionPointer = blockContext.initialIP (reset to block start)
   - Set blockContext.stackPointer = argumentCount (args on stack)
   - Set blockContext.caller = activeContext (for return)

4. Activate block context:
   - activeContext ← blockContext
   - Begin interpreting from initialIP
```

**Critical Detail**: primitiveValue does NOT return to caller - it's a **context switch**. The block bytecode executes until EndRemote (125) bytecode, which returns control to the caller context.

### Primitive 82: valueWithArguments: (Execute with Array)

**Source**: Formal Specification of the Primitive Methods, lines 1206-1238

**Same as primitive 81, but**:
- Takes single Array argument instead of multiple args
- Validates array is ClassArrayPointer
- Transfers from array indexed slots instead of stack

## BlockContext Field Layout (Blue Book Canonical)

### Instance Variable Indices

From Blue Book formal specification, BlockContext inherits from ContextPart (which inherits from Object):

**ContextPart fields** (lines 1152-1173):
```
sender:               CallerIndex       (set by primitiveValue to activeContext)
instructionPointer:   InstructionPointerIndex (set to initialIP by primitiveValue)
stackPointer:         (stored via storeStackPointerValue)
```

**BlockContext-specific fields** (lines 1168-1173):
```
nargs:                BlockArgumentCountIndex  (block argument count)
initialIP:            InitialIPIndex           (saved PC for re-execution)
home:                 HomeIndex                (lexical parent MethodContext)
```

### Critical Field Index Constants

The Blue Book specification uses these named indices (implementation must define actual integer values):

- **InitialIPIndex**: Slot where `initialIP` (instructionPointer + 3) is stored
- **InstructionPointerIndex**: Slot for current PC (reset from initialIP on each value)
- **BlockArgumentCountIndex**: Slot for `nargs` (block parameter count)
- **HomeIndex**: Slot for `home` (lexical parent MethodContext)
- **CallerIndex**: Slot for `sender` (dynamic caller, set by primitiveValue)
- **TempFrameStart**: First indexed slot (where block arguments/temps go)

### Indexed Slots (Temp Frame)

BlockContext has **indexed slots** (variable-length array) for:
1. **Block arguments** - placed by primitiveValue starting at TempFrameStart
2. **Block temporaries** - allocated after arguments
3. **Expression stack** - grows after temps

**Size determination**: `contextSize ← memory fetchWordLengthOf: methodContext` (line 1156)
- BlockContext gets SAME indexed slot count as its home MethodContext
- This provides space for all temps/args/stack that the block might need

## CRITICAL: Unified Temp Frame Architecture

**Date Added**: 2025-11-11
**Discovery**: Blue Book uses unified temp frame, NOT per-context temp frames

### The Unified Temp Frame Model

All temporaries (method args/temps + ALL nested block args/temps) are allocated in the **MethodContext's temp frame** using absolute indices. The compiler does NOT generate separate temp frames per context.

**Key Points**:
1. **Single allocation point**: All temps live in MethodContext indexed slots (slot 5+)
2. **Absolute indexing**: Compiler emits absolute indices (0, 1, 2...), not per-context relative indices
3. **Slot reuse**: Sequential non-overlapping blocks can REUSE temp slots
4. **Simplified VM**: No nargs+ntemps boundary checking, just traverse home chain and direct access
5. **BlockContext has NO ntemps field**: Blue Book spec has only 5 fields (nargs, startpc, home, plus inherited sender/pc/stackp)

### Example: Slot Allocation with Reuse

```smalltalk
myMethod: x
    | temp1 |                          "Slot 0: x, Slot 1: temp1"
    temp1 := x + 1.
    [| btemp1 | btemp1 := temp1].      "Slot 2: btemp1 (reuses after block exits)"
    [| ctemp1 ctemp2 | ctemp1 + ctemp2]."Slot 2: ctemp1, Slot 3: ctemp2 (REUSE slot 2!)"
    [:y | y + temp1]                   "Slot 2: y (REUSE slot 2 again)"
```

**Temp frame layout in MethodContext**:
```
Slot 0: x (method arg)
Slot 1: temp1 (method temp)
Slot 2: btemp1 / ctemp1 / y (REUSED for sequential blocks)
Slot 3: ctemp2 (only allocated when second block active)
```

**Maximum simultaneous need**: 4 slots (not sum of all temps!)

### BlockContext Indexed Slots: For Arguments ONLY

**CRITICAL CLARIFICATION**: BlockContext's indexed slots are used ONLY for:
- Block arguments during activation (primitiveValue copies args there)
- Expression stack during block execution

**BlockContext indexed slots are NOT used for**:
- Block temporaries (these live in home MethodContext)
- Permanent variable storage (compiler allocates in unified frame)

### Compiler Responsibilities

The compiler must:
1. **Analyze scope**: Determine which blocks are sequential vs nested
2. **Allocate slots**: Assign absolute indices with reuse for sequential blocks
3. **Track maximum**: Record maximum simultaneous slot need for method header
4. **Emit absolute indices**: PUSH_TEMP/STORE_TEMP use absolute indices into unified frame
5. **NO ntemps emission**: blockCopy: takes ONLY 1 argument (nargs), NOT 2

### VM Simplification

With unified temp frame, the VM temp access is drastically simpler:

**OLD (WRONG) - Per-context frames with nargs+ntemps logic**:
```csharp
// Complex home chain traversal with index adjustment
int GetLocalCount(contextOOP) {
    if (IsBlockContext) {
        nargs + ntemps  // Need to read ntemps field
    } else {
        method.numArgs + method.numTemps
    }
}
```

**NEW (CORRECT) - Unified frame with direct access**:
```csharp
// Simple home traversal, direct access
SmalltalkOOP FindHomeMethodContext(contextOOP) {
    while (!IsMethodContext(contextOOP)) {
        contextOOP = contextOOP.home;
    }
    return contextOOP;
}

void PushTemporary(int absoluteIndex) {
    var home = FindHomeMethodContext(_activeContext);
    Push(home.indexedSlots[absoluteIndex]);
}
```

### Why This Matters

**Memory efficiency**: Reusing slots reduces method temp frame size
**VM simplicity**: No complex nargs+ntemps boundary checks
**Blue Book compliance**: Matches canonical Smalltalk-80 implementation
**Correctness**: Enables proper nested block variable access

**Bug**: VM was doing hierarchical index adjustment (`index - nargs`) when traversing to MethodContext, but compiler emits absolute indices via TempFrameAllocator.

**Fix**: Changed VirtualMachine.cs lines 4147 and 4187 to use absolute indexing:

## Key Architectural Points

### 1. Blocks are NOT Literals
- **Myth**: Blocks are stored in literal array like strings/numbers
- **Reality**: Block bytecode is **inline** in method, jumped over during normal execution

### 2. BlockContext Created at Runtime
- **Myth**: Compiler creates BlockContext objects during compilation
- **Reality**: `blockCopy:` primitive creates fresh BlockContext each time bytecode executes
- **Blue Book Proof**: Line 1157 - `instantiateClass: ClassBlockContextPointer` happens DURING primitive execution

### 3. Lexical Scope via 'home'
- **Myth**: Blocks copy variables from outer context
- **Reality**: BlockContext has `home` pointer to defining MethodContext, delegates all temp access
- **Blue Book Proof**: Lines 1152-1155 - home set to methodContext, which is receiver if MethodContext or receiver.home if BlockContext

### 4. Block Body is Inline Bytecode
- **Myth**: Block body is separate CompiledMethod
- **Reality**: Block body bytecode is embedded in method bytecode stream, jumped over/into
- **Blue Book Proof**: Line 1159 - `initialIP ← instructionPointer + 3` points to bytecode AFTER the jump

### 5. Context Switch, Not Method Call
- **Myth**: Block invocation returns like a method call
- **Reality**: primitiveValue switches active context (trampoline), does not return
- **Blue Book Proof**: Line 1203 - `newActiveContext: blockContext` with no return value

**Required BlockNode Handling** (CORRECT - Unified Temp Frame):
```csharp
// CRITICAL: Use TempFrameAllocator for unified temp frame allocation

class TempFrameAllocator {
    // Allocates ALL temps (method + blocks) in unified frame
    // Reuses slots for sequential blocks
    // Emits absolute indices (0, 1, 2...)
}

void CompileMethod(MethodNode node) {
    _allocator = new TempFrameAllocator();
    _allocator.EnterMethodScope(node.Arguments, node.Temporaries);

    // Compile method body...

    _allocator.ExitScope();
    int maxFrameSize = _allocator.GetMaxFrameSize();
    EmitMethodHeader(node.Arguments.Count, maxFrameSize);
}

void CompileBlockNode(BlockNode node) {
    bool isNested = IsNestedBlock(node);
    _allocator.EnterBlockScope(node.Parameters, node.BlockTemps, isNested);

    // Generate inline bytecode
    Emit(0x89); // LdThisContext (137)
    EmitPushConstant(node.Parameters.Count); // ONLY nargs (NOT ntemps!)
    EmitSend("blockCopy:", 1); // Primitive 80 with 1 argument
    int jumpOffset = ReserveJump(); // Will fill in later

    // Emit block body inline (uses absolute indices from allocator)
    CompileBlockBody(blockNode);
    Emit(0x7D); // EndRemote (125)

    // Fill in jump offset
    FillJump(jumpOffset, currentOffset);

    _allocator.ExitScope();  // May reuse slots if sequential
}

void EmitPushTemporary(string varName) {
    // Get absolute index from allocator
    int absoluteIndex = _allocator.GetSlotIndex(varName);
    Emit(PUSH_TEMP, absoluteIndex);  // Absolute index into unified frame
}
```

```csharp
/// <summary>
/// Primitive 80: blockCopy:
/// Creates a new BlockContext for a block literal.
/// Blue Book: "Formal Specification of the Primitive Methods", lines 1146-1175
/// </summary>
public void PrimitiveBlockCopy()
{
    // Blue Book line 1150: blockArgumentCount ← self popStack
    var blockArgumentCount = popStack();

    // Blue Book line 1151: context ← self popStack
    var context = popStack();

    // Blue Book lines 1152-1155: Resolve home context
    SmalltalkOOP methodContext;
    if (isBlockContext(context))
    {
        // If receiver is BlockContext, use its home
        methodContext = memory.fetchPointer(HomeIndex, context);
    }
    else
    {
        // If receiver is MethodContext, it IS the home
        methodContext = context;
    }

    // Blue Book line 1156: contextSize ← memory fetchWordLengthOf: methodContext
    int contextSize = memory.fetchWordLengthOf(methodContext);

    // Blue Book lines 1157-1158: Allocate new BlockContext
    var newContext = memory.instantiateClass(
        ClassBlockContextPointer,
        contextSize  // Same indexed size as home
    );

    // Blue Book line 1159: initialIP ← memory integerObjectOf: instructionPointer + 3
    // NOTE: +3 because current PC points to blockCopy: send, need to skip 2-byte LONG_JUMP
    var initialIP = memory.integerObjectOf(instructionPointer + 3);

    // Blue Book lines 1160-1162: Store initialIP
    memory.storePointer(InitialIPIndex, newContext, initialIP);

    // Blue Book lines 1163-1165: Store instructionPointer (set to initialIP)
    memory.storePointer(InstructionPointerIndex, newContext, initialIP);

    // Blue Book lines 1166-1167: Initialize stack pointer to 0
    storeStackPointerValue(0, newContext);

    // Blue Book lines 1168-1170: Store block argument count
    memory.storePointer(BlockArgumentCountIndex, newContext, blockArgumentCount);

    // Blue Book lines 1171-1173: Store home context
    memory.storePointer(HomeIndex, newContext, methodContext);

    // Blue Book line 1174: Push result
    push(newContext);
}
```

### Critical Discoveries

**1. Blocks Are Inline Bytecode, Not Literals**
- Compiler generates: `LdThisContext + PUSH numArgs + SEND blockCopy: + LONG_JUMP + [block body] + EndRemote`
- Block body is embedded in method's bytecode stream
- LONG_JUMP skips over block body during normal method execution
- BlockContext created at RUNTIME by primitive 80, not at compile time

**2. BlockContext Object Structure (from Blue Book)**
```
Fixed Instance Variables:
  sender              (CallerIndex)         - Set by primitiveValue
  instructionPointer  (InstructionPointerIndex) - Reset from initialIP on each value
  stackPointer        (?)                   - Stack pointer
  nargs               (BlockArgumentCountIndex) - Block argument count
  initialIP           (InitialIPIndex)      - Saved PC (instructionPointer + 3)
  home                (HomeIndex)           - Lexical parent MethodContext

Indexed Slots (Temp Frame):
  [TempFrameStart + 0 .. n-1]  - Block arguments (placed by primitiveValue)
  [TempFrameStart + n .. m]    - Block temporaries
  [...]                        - Expression stack
```

**3. Primitive 80 (blockCopy:) Behavior**
- **Input**: Receiver = current context, Argument = SmallInteger (nargs)
- **Output**: New BlockContext instance
- **Key Steps**:
  1. Resolve home context (if receiver is BlockContext, use its home; else receiver IS home)
  2. Allocate BlockContext with same indexed size as home MethodContext
  3. Store initialIP = instructionPointer + 3 (points past LONG_JUMP to block body start)
  4. Store nargs, home, initialize stackPointer to 0
  5. Push BlockContext onto stack

**4. Primitive 81 (value) Behavior**
- **Input**: Receiver = BlockContext, Arguments = block arguments
- **Output**: CONTEXT SWITCH (no return value)
- **Key Steps**:
  1. Validate argument count matches BlockContext.nargs
  2. Transfer arguments from active context stack to block context temp frame
  3. Reset block's instructionPointer to initialIP
  4. Set block's caller to activeContext
  5. **Activate block context** - this is a trampoline, NOT a method call
  6. Block executes until EndRemote (125) bytecode returns control

**5. Why Our Offline Compiler Is Wrong**
- **Current**: Creates separate CompiledMethod objects, stores in literals, PUSH_LITERAL pushes them
- **Correct**: Must generate inline bytecode sequence with blockCopy: send
- **Impact**: Runtime sends `whileTrue:` to CompiledMethod (no such method) → FAILS
- **Fix Required**: Major refactoring of BlockNode bytecode generation

### Required Implementation Work

**Offline Compiler (Smalltalk80.Compiler)**:
1. Remove block-as-CompiledMethod logic
2. Implement inline bytecode generation:
