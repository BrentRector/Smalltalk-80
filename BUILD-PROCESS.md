# Build Process Documentation

## Solution Structure

The Smalltalk-80 solution uses a **shared bin directory** configured in `Directory.Build.props`:

```xml
<BaseOutputPath>$(MSBuildThisFileDirectory)bin\</BaseOutputPath>
```

This means all projects output to a common `Smalltalk-80/bin/` directory at the solution root.

### Output Directories

```
Smalltalk-80/
├── bin/
│   └── Debug/
│       ├── net9.0/                    ← Compiler output
│       │   ├── Smalltalk80.Compiler.exe
│       │   └── coldstart.json         ← Generated by Compiler
│       └── net9.0-windows/            ← Interpreter output
│           └── Smalltalk80.Interpreter.exe
├── Smalltalk80.Compiler/              ← Targets: net9.0
└── Smalltalk80.Interpreter/           ← Targets: net9.0-windows
```

## Build Dependencies

### Compiler Project (`Smalltalk80.Compiler`)
- **Target Framework**: `net9.0`
- **Output Directory**: `bin/Debug/net9.0/`
- **Post-Build Action**: Generates `coldstart.json` via `GenerateColdStart` target
- **Build Step**: Runs `Smalltalk80.Compiler.exe` on `Smalltalk-80.st` to produce `coldstart.json`

### Interpreter Project (`Smalltalk80.Interpreter`)
- **Target Framework**: `net9.0-windows` (requires Windows Forms)
- **Output Directory**: `bin/Debug/net9.0-windows/`
- **Dependencies**:
  - Engine project (normal reference)
  - Compiler project (`ReferenceOutputAssembly=false` - build dependency only)
- **Post-Build Action**: Verifies `coldstart.json` exists via `VerifyColdStartJson` target

## Build Process

### Top-Level Build (RECOMMENDED)

```bash
cd Smalltalk-80
dotnet clean
dotnet build
```

**What happens:**
1. MSBuild processes `Directory.Build.props` and sets `BaseOutputPath`
2. Cleans all projects (removes `bin/` and `obj/` directories)
3. Builds in dependency order:
   - Smalltalk80.Compiler.Core
   - Smalltalk80.Compiler (generates coldstart.json)
   - Smalltalk80.Interpreter.Core
   - Smalltalk80.Interpreter.Engine
   - Smalltalk80.Interpreter
4. Compiler's `GenerateColdStart` target runs → creates `bin/Debug/net9.0/coldstart.json`
5. Interpreter's `VerifyColdStartJson` target runs → confirms coldstart.json exists

**Result**: `bin/Debug/net9.0/coldstart.json` is generated and ready to use

### Project-Level Build (WORKS)

```bash
cd Smalltalk80.Interpreter
dotnet build
```

**What happens:**
1. MSBuild evaluates project dependencies
2. Builds Compiler first (due to `<ProjectReference>`)
3. Compiler's `GenerateColdStart` target runs → creates `bin/Debug/net9.0/coldstart.json`
4. Builds Interpreter
5. Interpreter's `VerifyColdStartJson` target runs → confirms coldstart.json exists

**Note**: Even with `ReferenceOutputAssembly=false`, the Compiler project is still built because MSBuild honors the build dependency.

### Running the Interpreter

```bash
cd Smalltalk80.Interpreter
dotnet run
```

**What happens:**
1. `dotnet run` triggers build (if needed)
2. Compiler builds and generates `coldstart.json` (if needed)
3. Interpreter builds and verifies `coldstart.json` exists
4. Program.cs locates `coldstart.json` using smart path resolution:
   - `exeDir` = `.../bin/Debug/net9.0-windows/`
   - `debugDir` = `.../bin/Debug/` (parent directory)
   - `compilerDir` = `.../bin/Debug/net9.0/` (sibling directory)
   - `coldStartFile` = `.../bin/Debug/net9.0/coldstart.json`
5. Interpreter loads coldstart.json and starts VM

## Path Resolution Logic

The Interpreter's `Program.cs` uses the following logic to find `coldstart.json`:

```csharp
// 1. Get executable directory (net9.0-windows/)
string exeDir = AppContext.BaseDirectory;

// 2. Get parent directory (Debug/)
string debugDir = Path.GetDirectoryName(exeDir)!;

// 3. Build path to compiler output directory (sibling net9.0/)
string compilerDir = Path.Combine(debugDir, "net9.0");

// 4. Check for coldstart.json in compiler directory
string compilerColdStart = Path.Combine(compilerDir, "coldstart.json");

if (File.Exists(compilerColdStart))
    coldStartFile = compilerColdStart;  // Use compiler's output
else
    coldStartFile = Path.Combine(exeDir, "coldstart.json");  // Fallback
```

This works for both:
- **Shared bin structure** (Directory.Build.props): `.../bin/Debug/net9.0/coldstart.json`
- **Project-local bin** (no Directory.Build.props): `.../Smalltalk80.Interpreter/bin/Debug/net9.0/coldstart.json`

## Troubleshooting

### Problem: "coldstart.json not found"
**Cause**: Compiler hasn't built yet
**Solution**: Run `dotnet build` from solution root

### Problem: Compiler doesn't rebuild when source changes
**Cause**: Incremental build skipping unchanged projects
**Solution**: `dotnet clean && dotnet build` or touch the .st file

### Problem: Wrong coldstart.json version
**Cause**: Multiple coldstart.json files in different directories
**Solution**: Run `dotnet clean` to remove all old files, then `dotnet build`

## Best Practices

1. **Always build from solution root** for initial builds
2. **Use `dotnet clean` before major changes** to ensure fresh build
3. **Check build output** for `✓ coldstart.json found` message
4. **Run tests after rebuilds** to verify no regressions
